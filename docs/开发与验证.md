# 开发与验证记录

## 确认范围

Windows 11 自用桌面应用，一个当前登录账号。左侧菜单、中间群聊列表、右侧仿微信消息阅读。支持单群逐条勾选或日期范围导出；v0.1.5增加多群统一日期批量导出，可选择合并或分开保存 HTML。文字和本地可解码图片保留内容。语音、转写、OCR、附件内容提取、任务分析、后台同步和手机历史迁移暂不实现。

## 实现

C# / WPF 桌面界面，Python 3.14 独立读取进程，通过标准输入输出交换本地 JSON；不启动网络服务。界面采用系统中文字体、浅色背景和绿色操作按钮。

读取只授予微信进程查询与读取权限（0x410），不注入、不 Hook、不写微信内存。通过 WCDB Config.Cipher 对象恢复候选，逐数据库验证首页 HMAC；通过实际可读的 session.db 确认账号。存在多个历史账号目录时，只选唯一通过当前进程密钥校验的账号。

读取前快速复制数据库与 WAL，核对复制前后文件元数据；随后对副本解密。逐页验证 HMAC，检查 WAL 头与帧校验和、盐、完整提交边界，合并已提交页，最后执行 SQLite quick_check。缓存位于当前工作区 private/cache。

按群表与时间条件查询，按时间、sort_seq、本地ID排序；分页保留同秒全部消息，避免分页边界遗漏。群成员名字通过每个消息分片自身 Name2Id 解析。HTML 转义消息内容并禁止外部资源与脚本，图片使用 data URI 内嵌。

图片按消息正文与 packed_info_data 中的哈希匹配群附件，比较所有匹配文件的真实像素尺寸，选择像素最多的可读取版本。图片密钥优先从本机 kvcomm 配置派生并用图片头校验，未命中时才尝试带超时的只读内存候选验证。无可用资源时显示占位，导出完成后报告缺失和缩略图数量。

## 限制

当前仅适配本机环境，并非经过跨设备与长时间运行验收的发布版。微信升级后的对象布局或掩码变化需要重新验证。数据副本不自动持续刷新，再次连接可更新。

支持文字、常见JPEG/PNG/GIF/WebP本地图片及下述本地卡片文字解析；部分微信特殊图片容器暂未转换。语音、视频、动态表情等保留类型占位。图片缺失、只保留缩略图或不支持的格式不会被冒充为已恢复原图。

private/cache 包含可读聊天副本，供本机程序使用；不纳入版本管理。应用退出不会删除缓存，用户可在关闭应用后删除该目录重新生成。密钥不持久保存。

## 2026-10-20 本地卡片解析

版本 0.1.1 新增 `src/message_content.py`，仅解析现有消息字段，不访问网页，不使用微信界面或浏览器自动化。

- `local_type` 取低32位，再解析 `appmsg/type`：5为网页分享（依据公众号域名/来源区分文章）、6为文件、57为引用回复、62为拍一拍、2000为转账、2001为红包；19、33/36、51分别标记合并聊天记录、小程序和视频号。其他未知子类型保留类型号及可用标题。
- 标题、网址、公众号、摘要来自本地字段。原始网址保留；导出文章编号优先使用 `__biz + mid + idx`，其次为 `/s/短链接标识`，其余只对相同完整网址匹配；完整标识字段重复或不完整时不按文章参数合并。不根据标题猜测同一文章。
- 引用支持有限层级展开，保留引用者名称、回复文字及引用内容。直接粘贴的公众号链接也参与导出编号；编号仅在本次导出文件内有效，重新筛选可能变化。
- 拍一拍使用联系人名称替换本地模板占位；红包/转账只保留提示和备注，不输出交易标识、支付深链，不推断实时交易状态。
- XML 拒绝 DTD/实体声明，限制大小、树深度和引用递归层级。异常卡片或压缩字段损坏时使用占位；HTML 全部转义，仅为已验证的 HTTP/HTTPS 网址生成可手动点击的链接，保持禁止脚本及外部资源自动加载的策略。
- WPF 中的消息文字改为可选择的只读文本，支持复制标题、网址和内容。`--render-preview` 使用合成文章、引用回复和拍一拍示例。

验证命令：`python -m unittest discover -s tests -v`，包含原有回归与新增合成卡片、压缩字段、子类型高位、日期/勾选导出、安全及文章匹配测试。`python tools/check_cached_cards.py` 对已有缓存进行有数量和时间上限的只读抽样，只打印分类与数量，不输出原文、网址、账号或支付标识。

本轮14项测试通过，400条缓存消息抽样中30处文章信息（含引用）均有本地标题，无卡片XML或拍一拍模板占位残留。从最终读取EXE抽取实际封装的解析模块后，同样14项测试通过；读取EXE在无Python PATH下通过离线协议启动检查，桌面EXE在无外部.NET路径下生成合成界面预览。完整打包成功，仅有原有NU1900网络漏洞审计警告。未在本轮进行微信进程扫描或线上文章请求。

## 2026-10-20 本地大图与 WXGF 兼容（0.1.2 开发版）

- 新增 `image_resources.py`，收集正文 `md5`、`cdnthumbmd5`、`originsourcemd5` 及 packed_info_data 中的完整哈希，在当前账号的对应聊天附件目录内匹配资源。不混用其他聊天文件，不覆盖同名跨月份候选；比较全部可解码候选的像素数量，像素相同时才优先大图/普通图片来源。
- 新增 `image_codec.py`，从可识别 WXGF 容器定位 HEVC VPS 数据流，通过固定版本 PyAV 19.0.1 与随附 FFmpeg 动态库转换为 PNG，保留像素尺寸。常见图片保留原始字节。多数据流优先彩色首帧，对动画/透明效果不宣称完整还原，并显示说明。
- 解码使用可复用的独立隐藏子进程，通过内存管道传递字节，不落盘真实解密图片；单次请求15秒超时，错误或崩溃可回退其他本地图片。输入上限64 MiB，图片上限3200万像素，超限明确作为不可用候选处理。
- 图片索引在每次读取消息或导出时更新，以便发现后来下载的大图。图片说明区分仅找到缩略图、其他本地候选不可用、所有关联文件缺失，以及定位信息不足；显示所选资源的真实尺寸，不根据文件名声称恢复原图。
- WPF 主列表使用有尺寸限制的预览解码，原始数据仍供导出；“查看大图”以原像素尺寸显示并提供滚动条。HTML 用原生 details/summary 实现点击或键盘切换图片尺寸，保持单次图片嵌入、单文件、不含脚本及禁止外部资源自动加载的策略。
- 29项回归测试通过，包含15项新增图片测试和原有14项。合成 HEVC 样本由本项目自行生成，不包含真实聊天图片；覆盖跨哈希/跨月选图、新下载文件重新索引、原字节保持、WXGF尺寸/颜色、损坏回退、工作进程复用与超时退出，以及由可验证的JPEG缩略图恢复尾部XOR字节后解码大图。
- 50条现有缓存图片只读对比中，22条选到了比旧版更大尺寸的图片，0条尺寸下降。新版选用26份普通图片、2份大图、22份缩略图；22份选中的 WXGF 已转 PNG，最大所选尺寸3072×3416。这里只说明本机抽样结果，不保证所有图片或格式都能恢复。
- `tools/check_local_images.py` 不刷新数据库、不扫描微信进程，不导出真实图片，仅输出对比统计。`tools/check_image_package.py` 用合成样本在无外部Python PATH下验证真实封装EXE解码、保持960×540尺寸并拒绝损坏数据。独立WPF EXE的合成图片预览启动通过。
- 合成 HTML 浏览器验证：页面预览宽度782像素，点击后以960像素原始宽度展开并出现内部滚动条；空格键可恢复预览。此检查仅使用合成图片，不操作微信。
